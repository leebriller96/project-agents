# 에이전트셋 설계 체크리스트

한 기능·한 단계를 여러 에이전트로 나눌 때 **미리 정하지 않으면 나중에 전부 되돌려야 하는 것**들의 목록이다.
새 stage·새 에이전트를 추가하거나 기존 단계를 쪼갤 때 이 표를 먼저 훑는다.

출처: 외부 에이전트 repo `ing-people/sk-secu-agent` 의 `docs/에이전트셋_설계_고려사항.md`(2026-09-23 검토)를
우리 파이프라인 규칙과 대조해 각색했다. `우리 규칙` 열은 이미 반영된 곳이고, `미도입` 은 의도적으로 채택하지 않은 것이다.

---

## 1. 착수 전 확정

| 항목 | 왜 | 우리 규칙 |
|---|---|---|
| 대상 브랜치 | 브랜치가 다르면 패키지 구조·인증·모듈 구성이 통째로 다를 수 있다. 코드 파악보다 브랜치 확정이 먼저다 | `pa-meta.repo.branch` 기재 + `gate.py` 가 실제 브랜치와 대조 (pipeline-core §9) |
| 작업 트리가 깨끗한가 | 남의 미커밋 변경 위에서 시작하면 되돌릴 수 없다 | `pa-meta.repo.dirty` 실측 대조 |
| 산출물 경로·파일명 | 나중에 바꾸면 모든 문서의 경로 문자열을 일괄 치환해야 하고 누락이 남는다 | `pipeline-core §2`(workspace/target_dir 분리), §9(레포트 파일명 KST 접두어) |
| 실행 도구 | 도구가 바뀌면 에이전트 등록 위치·모델 표기·호출 문법이 전부 달라진다 | Claude Code 고정 (`docs/DESIGN.md` §3) |

## 2. 분할 기준 — 화면·업무별로만 나누면 실패한다

- **공유 지점을 먼저 목록화한다.** 상태 머신, 권한 판정, 외부 경계 adapter(파일·메일·ID 생성), 라우터·레이아웃 같은
  단일 파일, 공용 UI·토큰·문구 상수. 이건 slice 가 아니라 **골격 또는 공통화가 소유**한다.
  → 우리: 2단계 골격 1회(`stage2-backend §A`) + 3단계 공통화. slice 가 필요로 하면 `common-candidates.md` 로 올린다.
- **수직 슬라이스로 준다.** 한 업무의 BE·FE 계약 드리프트를 사람이 중재하지 않으려면 계약이 단일 원천이어야 한다.
  → 우리: slice 별 OpenAPI 계약이 2단계 산출·4단계 소비. FE 는 BE 소스를 읽지 않는다.
- **여러 slice 가 호출하는 API 는 소유자를 지정한다.** 지정하지 않으면 두 에이전트가 같은 컨트롤러를 각자 만든다.
  → 우리: `slices.yaml` 의 `depends_on` + 계약 파일 소유. 공유 API 는 선행 slice 소유, 후행은 호출만.
- **숨은 의존(같은 라우트·같은 분기 파일)을 찾는다.** 앞 에이전트가 분기 파일과 **슬롯**을 만들고 뒤가 끼워 넣는다.
  → 우리: 라우터·메뉴처럼 단일 파일은 골격이 placeholder 로 **선점 등록**하고 slice 는 자기 페이지 파일만 교체한다.
- **책임이 애매한 로직**(조회 시 부수 기록 등)은 "공통이 메서드로 제공, slice 는 호출만" 으로 문장으로 못박는다.

## 3. 파일 소유권

| 규칙 | 내용 |
|---|---|
| 배타 소유 | 디렉토리 단위로 나누되 경계에 걸친 파일은 개별 지정 (`pipeline-core §6-4`) |
| 우회로 필수 | 소유가 아닌 파일이 막히면 **몰래 고친다.** 반드시 우회로를 준다 → `common-candidates.md` 에 "무엇이·왜" 를 남기고 slice 안에 임시 구현 |
| 단일 공유 파일 | 골격이 모든 경로를 placeholder 로 선점 등록 → 이후 slice 는 그 파일을 만지지 않는다 |
| 공유 상수 파일 | 완전 금지하면 작업이 막힌다. **네임스페이스 분할**로 예외: "자기 slice 접두어 아래 항목 추가만 허용" |
| 도메인당 1파일이 되기 쉬운 것 | Mapper XML·API 클라이언트 모듈은 소유자별로 파일을 미리 쪼개 이름을 정해 준다 |
| 번호 대역 | 공통 후보 C-번호·결함 F-번호는 slice 마다 대역을 배정한다 (안 적어서 충돌 2회) |
| 검증 | 에이전트의 `changed_files`(pipeline-core §12) ↔ `git diff` 대조. 소유 밖 파일이면 되돌린다 |

## 4. 에이전트 문서

- **원본은 한 곳, 실행 등록은 포인터.** 같은 지침을 두 곳에 복사하면 드리프트가 생긴다
  → 우리: 방법론은 `.claude/skills/`, 에이전트 문서는 역할·금지·보고 형식만.
- **self-contained.** 선행조건 확인 → 참조 문서 목록 → 금지 목록 → DoD → 보고 형식이 한 문서에 다 있어야 한다.
- **금지 목록을 명시한다.** "무엇을 하라" 만 쓰면 범위를 넘는다.
- **DoD 는 실행 가능한 명령으로.** "테스트 통과" 가 아니라 실제 명령과 확인 대상(개수·종료 코드)을 적는다
  → 우리: `pa-meta.gates[]` 가 그 자리다.
- **참조 문서를 제한한다.** 전체 기획서를 다 읽히면 컨텍스트가 낭비된다 (brief + 자기 slice 원문).

## 5. 중간 산출물과 인계

- 지침 폴더와 산출물 폴더를 분리한다 → 우리: `.claude/`·`docs/` vs `workspace/<project>/`.
- 구현 repo 에는 파이프라인 문서를 남기지 않는다 → 우리: `target_dir` 에는 소스와 계약·시나리오만.
- 보고 고정 항목: **완료 범위 / 검증 결과 / 계약 이행 / 공통 변경 요청 / 다음 에이전트 주의사항**
  → 우리: `pa-agent-result` 블록 (pipeline-core §12).
- **"실패 은폐 금지" 를 명문화한다.** 없으면 통과한 것만 적는다 → 우리: `not_executed[]` 필수 + `gate.py` 의 `gate-proof`.
- 후행 에이전트가 선행 보고를 읽는 것을 선행조건으로 두고, 없으면 중단하고 보고하게 한다.

## 6. 실행 순서와 동시성

- **같은 작업 트리를 함께 쓰는 에이전트는 파일이 겹치지 않아도 빌드·인덱스가 섞인다.**
  → 우리: 병렬 developer 는 slice 디렉토리만 쓰고, 전체 빌드·전체 테스트는 웨이브 종료 후 오케스트레이터가 1회 (pipeline-core §6-6).
  포트·스크래치패드 파일명도 slice 별로 분리한다.
- **커밋 정책을 정한다.** 우리: 서브에이전트는 커밋하지 않는다. 웨이브 종료 시 오케스트레이터가 커밋(§6-7).
- **QA·검토 에이전트는 코드를 고치지 않는다.** 결함은 RR 로 돌려 소유 에이전트를 재호출한다.
- 재시도: 서브에이전트가 API 오류로 끊기면 새로 띄우지 말고 같은 에이전트를 재개(`SendMessage`)한다 (실측 2회).

## 7. 모델 배정

`pipeline-core §13`. 상위 모델은 (1) 실수가 전파되는 공용·골격, (2) 분기가 얽힌 slice, (3) 단계를 가로지르는 검증에만.
중급 에이전트가 같은 문제로 2회 이상 막히면 그 에이전트만 상위로 재실행한다.

## 8. 계약

- API 계약은 **단일 원천 문서 하나**. 바꿔야 하면 문서를 먼저 고치고 보고에 남긴다.
- 권한 판정은 서버가 하고 화면은 소비만 한다(응답에 액션 가능 플래그).
- 상태 라벨·문구는 메타 한 곳만 참조. 컴포넌트 하드코딩 금지 (우리 실측: 문구 3중 복제 → `Msg` 상수 + 리플렉션 대조).
- **계약 누락 역검증**: 화면 목록 기준으로 "이 화면이 호출할 API 가 계약에 다 있나" 를 되짚는다.

## 9. 자주 빠뜨리는 것

- 문서 간 **수치 불일치**(테이블 N종·컴포넌트 N종). 한 문서를 원천으로 삼고 나머지는 인용한다.
- **placeholder 라우트 개수 ↔ 실제 화면 수** 대조.
- 테스트 프레임워크·도구 도입 주체 지정 (아무도 안 하거나 여러 에이전트가 각자 한다).
- 공유 컴포넌트는 "import 재사용만 허용, 수정 금지" 를 명시.
- 한 커밋 안에 공용 본체와 slice 연동이 섞이면 소유가 둘에 걸친다. 커밋을 쪼갠다.

## 10. 미도입 (검토 후 제외)

| 외부 repo 의 방식 | 제외 이유 |
|---|---|
| 중앙 포털 API 로 claim/lease 동시성 제어 | 우리는 단일 오케스트레이터가 웨이브를 통제한다. `state.yaml` 로 충분하고, 외부 서비스 의존을 만들지 않는다 |
| slice 마다 git worktree 필수 | 우리 실측에서 worktree 의 `node_modules` 처리가 실제 repo 를 손상시킨 사고가 있었다. 포트·디렉토리 분리 + 전체 빌드 1회가 더 안전했다 |
| 리뷰어 6축을 별도 에이전트로 분리 + synthesizer | 비용 대비 효과가 불명확. 대신 reviewer 지적에 `confidence`·`test_hint` 를 넣어 인계를 끊기지 않게 했다 (pipeline-core §7) |
| AS-IS 픽셀 패리티 캡처 증적(PNG)·visual compare 에이전트 | 우리 4단계 근거는 피그마·스토리보드다. 다만 **차세대(migration) 모드에서 AS-IS 화면이 있는 경우** 화면 증적 비교는 채택 후보로 남긴다 |
